  states it for every row: a response is retryable when it invites the person to
  act again and the action may succeed without correcting a value it reports; a
  response whose only action is to correct a value it reports, or which reports a
  settled condition, is not retryable; a retryable response states no interval of
  its own, a limit's window
  alone deciding when a repeat is accepted. The contract's `retryable` flag now
  cites that definition, and `OTP_INCORRECT` no longer carries it because its
  message states a fault in the supplied code.
- **CHK006 — closed.** Placement is stated per row in six terms — `field`,

  catalogue maps the four refusals among them to exceptions 3 to 6 and names the

  or outside the comparison's subject rather than excepted from it.
- **CHK013 — closed.** Each response is classified exactly once, and the fifth
  incorrect entry is the test case: it is a **notice**, because its response
  reports that the request ended rather than a fault in the code entered, the code

  it. The contract lists it as a notice rather than among the refusals, the
  message table carries one text for it, and the duplicate "Attempts ended
  (status, not an error)" row is withdrawn. The silent hidden-field response is a
  refusal, because silence is a rendering and the submission was not carried out,
  and the three post-verification messages are outcome messages, not refusals.
