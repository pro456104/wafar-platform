# Project-Technologies.txt — the detail of the technology register

**Status**: detail mirror, not a source of rules. The register is
`.specify/memory/constitution.md` → **Technology Standards**; on any conflict the
register wins and this file is corrected. ADR-008 and ADR-010 record the decision.

**What lives here**: the exact version of each approved technology, the note that
explains why it was chosen, and the repository trees at file granularity — the
detail a reader wants while implementing.

**What does not live here**: any rule. The gaps a slice closes, the MAJOR/MINOR
version-change rule, and the licence treatment for infrastructure services exist
only in the register. The constraints on this file — the technologies it may name
and the way it may restate them — are the register's, stated there and not here
(constitution → Single-Reference Sufficiency).

## 🏗️ أولاً: البنية الأساسية (Monorepo Architecture)

| التقنية | الدور | التفاصيل |
|---|---|---|
| **Monorepo** | مستودع واحد يجمع كل التطبيقات والحزم | يضم: `apps/web`، `apps/admin`، `apps/api`، `apps/worker` + `packages/shared`، `packages/db`، `packages/search`، `packages/config`. يسهّل مشاركة الكود والأنواع بين الواجهة والخادم. |
| **pnpm** | مدير الحزم | أسرع من npm/yarn، يوفر مساحة القرص عبر الروابط الصلبة (Hard Links). يدعم **pnpm Catalogs** لإدارة الإصدارات المركزية في Monorepo. |
| **Turborepo** | منسق المهام والبناء | يشغّل `build`، `test`، `lint` عبر كل الحزم بأمر واحد. يخزّن النتائج مؤقتاً (Caching) فلا يعيد البناء إن لم يتغير شيء. يبني الحزم بالترتيب الصحيح (shared ← web). الإصدار v2.8 مستقر. |

### 📁 بنية Monorepo التفصيلية

```
wafar/
├── apps/
│   ├── web/              # الموقع العام (Nuxt 4)
│   ├── admin/            # لوحة الأدمن (Nuxt 4) — بنية داخلية مماثلة لـ apps/web وتشمل layouts/
│   ├── api/              # الخادم (Hono)
│   └── worker/           # معالج الملفات (BullMQ)
├── packages/
│   ├── shared/           # Zod schemas + الأنواع + العقود
│   ├── db/               # Drizzle schema + migrations
│   ├── search/           # OpenSearch client + mappings
│   └── config/           # ESLint + Prettier + TS config
├── pnpm-workspace.yaml
├── turbo.json
└── package.json
```

## ⚙️ ثانياً: الواجهة الخلفية (Backend API)

| التقنية | الدور | التفاصيل |
|---|---|---|
| **Modular Monolith** | النمط المعماري للخادم | خادم واحد مقسّم إلى وحدات مستقلة (auth, users, catalogs, parts, suppliers, bookmarks, notifications, messages, support, admin). كل وحدة لها `routes`، `service`، `repository` خاص. لا استدعاء مباشر بين الوحدات — التواصل عبر `shared/`. |
| **Hono** | إطار الخادم | إطار خفيف فائق السرعة. الإصدار 4.13.5 (2026). حقق **88,525 طلب/ثانية** في اختبارات Node.js. يعمل على Node.js، Bun، Deno، Cloudflare Workers. |
| **OpenAPI** | توثيق الـ API | توليد توثيق تلقائي من نفس كود Hono. يضمن تكاملاً سلساً بين الواجهة والخادم. |
| **Zod** | التحقق من صحة البيانات | الإصدار 4.6 (2026). `.validate()` أسرع بـ **35x** من `safeParse().success`. يُستخدم في الواجهة والخادم معاً لمشاركة نفس schemas. |

## 🎨 ثالثاً: الواجهة الأمامية (Frontend)

| التقنية | الدور | التفاصيل |
|---|---|---|
| **Nuxt 4** | إطار العمل | الإصدار 4.0 صدر يوليو 2025. الإصدار الحالي **4.5** (يوليو 2026). Nuxt 3 وصل EOL في 31 يوليو 2026. |
| **Vue 3** | لغة بناء الواجهات | Composition API + `<script setup>`. |

| **Nuxt UI** | مكتبة مكونات جاهزة | الإصدار **v4.11.2** (سبتمبر 2026). 125+ مكون و12 قالباً وFigma Kit. مجاني بالكامل. |
| **Pinia** | إدارة الحالة المحلية | الإصدار **v3.0.4** (يناير 2026)، و**v4.0** (يوليو 2026). المكتبة الرسمية لـ Vue. |
| **TanStack Query (Vue)** | إدارة بيانات الخادم | الإصدار v5. يدعم `useQueries`، `useQuery`، التخزين المؤقت، التحديثات التلقائية، Infinite Scroll، Optimistic Updates. |
| **Zod** | التحقق من صحة البيانات | (مذكور في الخادم) — يُستخدم أيضاً في الواجهة. |

## 🗄️ رابعاً: قاعدة البيانات والاتصالات

| التقنية | الدور | التفاصيل |
|---|---|---|
| **PostgreSQL** | قاعدة البيانات الرئيسية | الإصدار 16+. تخزين المستخدمين، الموردين، الملفات، القطع، السلة، الإشعارات، المراسلات، Audit Log. |
| **Drizzle ORM** | وسيط قاعدة البيانات | **48.1 مليون تحميل** (يوليو 2026). كل شيء في TypeScript. يستنتج الأنواع هيكلياً بدلاً من خطوة توليد منفصلة. خفيف وسريع. |
| **PgDog** | مجمّع الاتصالات | الإصدار **v0.1**. مكتوب بلغة **Rust**. بديل PgBouncer. يدير **آلاف الاتصالات** على أجهزة عادية. أسرع من PgBouncer عند تجاوز 50 اتصالاً. مرخّص **AGPL-3.0**. |

## 📁 سادساً: تخزين ومعالجة الملفات

| التقنية | الدور | التفاصيل |
|---|---|---|
| **SeaweedFS** | تخزين الملفات | الإصدار **v4.48** (سبتمبر 2026). مرخّص **Apache 2.0**. بديل MinIO (الذي توقف عن التطوير أبريل 2026). يتعامل مع كميات هائلة من الملفات الصغيرة بكفاءة. |
| **BullMQ** | طابور المهام | يدعم ioredis، node-redis، Bun's Redis client. يدعم أيضاً **PostgreSQL** كخلفية للطوابير. |
| **Redis** | خلفية الطابور + التخزين المؤقت | عاد لرخصة **AGPLv3** المفتوحة. BullMQ يتطلب **Redis >= 5.0.0**. |
| **Worker** | معالجة الملفات في الخلفية | استخراج القطع، توحيد الأعمدة، إزالة التكرار، الفهرسة في OpenSearch. |
