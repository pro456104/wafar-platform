# Project-Technologies.txt — the detail of the technology register

**Constitution**: `.specify/memory/constitution.md` v2.17.0 (last amended
2026-10-04, ADR-037/ADR-038). On any conflict with this file, the constitution
wins and this file is corrected.

**Status**: detail mirror, not a source of rules. The register is
`.specify/memory/constitution.md` → **Technology Standards**; on any conflict the
register wins and this file is corrected. ADR-008 and ADR-010 record the decision.

**What lives here**: the exact version of each approved technology, the note that
explains why it was chosen, and the repository trees at file granularity — the
detail a reader wants while implementing.

**What does not live here**: any rule. The 80% coverage gate (Principle III),
the dependency policy (Dependency Governance), the gaps a slice closes, the MAJOR/MINOR
version-change rule, and the licence treatment for infrastructure services exist
only in the register. The constraints on this file — the technologies it may name
and the way it may restate them — are the register's, stated there and not here
(constitution → Single-Reference Sufficiency).

## Constitution 2.11.0 additions (2026-10-03, ADR-023)

Mirrors the binding controls added by ADR-023. It records the technologies only;
the rules stay in `.specify/memory/constitution.md`.

- **ClamAV** — antivirus scanning of uploaded files, mandatory before processing.
- **Stylelint** (+ ESLint) — fails the build on physical direction properties and on design values that do not reference a `wafar.single.css` token.
- **Lighthouse CI** — LCP/INP/CLS budget asserted on the public Parts and Home pages.
- **Semgrep OSS** (or equivalent) + **osv-scanner** — SAST and vulnerability scanning that block release; SBOM produced per build.
- **Prometheus + Grafana** — p95 request latency, search p95, processing success rate, queue depth, with alerting on budget breach.
- **BullMQ** — bounded retries with exponential backoff, dead-letter queue, per-worker concurrency cap, temporary-file sweep.
- **SeaweedFS presigned multipart uploads** — direct-to-object-storage; the API never buffers the uploaded file. The size ceiling is the constitution's Usage Limits.
- **pg_anonymize** (or equivalent) — staging holds no production personal data.
- Content-safety tools — magic-byte validation, ClamAV, decoded-size cap, and macro stripping; the pipeline order and the cap's rule are the constitution's (File Processing Rules, File Processing Overview).
- **API versioning** — the deployment version prefix is `/api/v1`; the removal-notice rule is the constitution's (Deployment and Observability).
- **Session revocation** — server-side revocation of every authenticated session, including "sign out everywhere" and browser-stored tokens on password change; the mandate is the constitution's (Identity, Authentication, and Session Policy).
- Account-protection controls — the tools that enforce uniform responses, an attempt/window lockout, honeypot fields, a minimum time-to-submit, per-client rate limits, the CAPTCHA prohibition, and the seeded administrator CLI with its forced first-sign-in password change. The numeric values are the constitution's (Identity, Authentication, and Session Policy); this mirror restates none of them.
- **Tenant isolation verification** — the query-path test that fails the build when a merchant-reachable path returns another tenant's rows; the mandate is the constitution's (Deployment and Observability).
- **Browser coverage** — where the plan states its supported browsers (constitution → Design System Standards → Supported browsers, recorded under Constitution Mandated Values); this mirror names no browser set of its own.
- Design-system tokens — `ds-table-density-compact|normal|comfortable`, `--duration-fast|base|slow|slower`, the honoured media/capability states (`ds-touch-optimized`, small-screen handling); a sticky table header is a required missing component tracked in the constitution's missing-components list.

## Constitution 2.13.0 additions (2026-10-03, ADR-030)

Mirrors phone-only authentication.

- **better-auth phone-number extension** — provides the phone-number sign-in
  and OTP flows; custom authentication code remains prohibited. `scim`/`sso`
  stay disabled (CVE-2026-67330, CVE-2026-80192).
- **Transactional SMS provider** (international, e.g. Twilio or Vonage) — OTP
  at sign-up and password-reset delivery. Owned by R1, per the register-gap
  rule (choice, licence record, vulnerability scan recorded in R1's plan).
- **E.164 mobile number** — the identifier format the phone-number extension
  stores; the choice of identifier itself is the constitution's (Identity,
  Authentication, and Session Policy; ADR-030).

## Constitution 2.14.0 additions (2026-10-04, ADR-033)

Mirrors the audit fix set. No new technology was introduced; no new dependency
or licence obligation.

- **Merchant full name** — a field the sign-up schema collects through
  `packages/shared`; the register entry for it is the constitution's
  (Product Register; ADR-033).
- **`/speckit.analyze` timing** — where the consistency gate sits in the cycle
  is a workflow rule; the workflow file and the constitution (Artifact Workflow
  and Traceability) own it, and this mirror records no ordering of its own.
- **Catalog-delete cascade** — implemented once in the `catalogs` module service
  and reused downstream; which slice owns it is ROADMAP.md's record (R4), not
  this mirror's.
- **Single shared entry point** — the one channel through which tenant scoping
  is applied; the owning slice and the permission model's ratification are
  ROADMAP.md's (R2, then R13).
- **Dependency budget** — the numeric cap on direct runtime dependencies is
  recorded under Constitution Mandated Values; R1 owns setting it.
- **Mirror claims cleanup** — unsourced or unverifiable figures (a Zod
  `.validate()` 35x claim, an exact Hono benchmark number, a Nuxt 3 EOL
  date) were replaced by neutral wording. A mirror MUST NOT carry a precise
  figure it cannot attribute to its vendor source.

## Constitution 2.16.0 + 2.17.0 additions (2026-10-04, ADR-037/ADR-038)

- **Cart label** - the cart page's user-facing Arabic label is a product fact
  fixed by the constitution (Product Scope; ADR-038). Where this mirror shows
  the cart's path or its table row, it shows that constitution label and states
  no label of its own.
- **Trade name** - the product name and its mandatory diacritics are registered
  in the constitution (Glossary; ADR-038); no technology row depends on them.
- **Reports** - the admin Dashboard's reports are built from in-scope entities;
  the limit itself is the constitution's (Product Scope; ADR-038).
- **Worker re-runs** - retry (merchant) and reprocess (administrator) both
  re-enqueue BullMQ jobs over stored bytes; the two definitions are the
  constitution's Glossary (ADR-038).
- **ClamAV and Lighthouse CI** - registered in the constitution (Technology
  Standards) with explicit notes that they are gates, not runtime dependencies.
- **Nitro** - named as part of Nuxt 4 in Internal layout (`apps/web/server/`);
  deliberately not a row of the Approved register.
- **Role split** - design components come from Nuxt UI v4, module stores from
  Pinia, server-state cache from TanStack Query; validation schemas live in
  `packages/shared`.
- **Open register gaps** (owners in parentheses): Redis client library for
  BullMQ (R3), OpenSearch client library (R5), automated accessibility checker
  (R1), Arabic analyzer configuration and verification (R5).
- **Module size** - advisory; the rule and its exception route are the
  constitution's (Module Discipline and Development Workflow).
- **Shared location** - `packages/shared` is the API's only cross-module
  channel; `apps/api/src/shared` is not a location (constitution → Module
  Discipline; ADR-038).
