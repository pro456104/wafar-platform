# Project-Technologies.txt — the detail of the technology register

**Status**: detail mirror, not a source of rules. The register is
`.specify/memory/constitution.md` → **Technology Standards**; on any conflict the
register wins and this file is corrected. ADR-008 and ADR-010 record the decision.

**What lives here**: the exact version of each approved technology, the note that
explains why it was chosen, and the repository trees at file granularity — the
detail a reader wants while implementing.

**What does not live here**: any rule. The 80% coverage gate (Principle III),
the dependency policy (Dependency Governance), the gaps a slice closes, the MAJOR/MINOR
version-change rule, and the licence treatment for infrastructure services exist
only in the register. The constraints on this file — the technologies it may name
and the way it may restate them — are the register's, stated there and not here
(constitution → Single-Reference Sufficiency).

## Constitution 2.11.0 additions (2026-10-03, ADR-023)

Mirrors the binding controls added by ADR-023. It records the technologies only;
the rules stay in `.specify/memory/constitution.md`.

- **ClamAV** — antivirus scanning of uploaded files, mandatory before processing.
- **Stylelint** (+ ESLint) — fails the build on physical direction properties and on design values that do not reference a `wafar.single.css` token.
- **Lighthouse CI** — LCP/INP/CLS budget asserted on the public Parts and Home pages.
- **Semgrep OSS** (or equivalent) + **osv-scanner** — SAST and vulnerability scanning that block release; SBOM produced per build.
- **Prometheus + Grafana** — p95 request latency, search p95, processing success rate, queue depth, with alerting on budget breach.
- **BullMQ** — bounded retries with exponential backoff, dead-letter queue, per-worker concurrency cap, temporary-file sweep.
- **SeaweedFS presigned multipart uploads** — direct-to-object-storage; the API does not buffer a 100 MB file.
- **pg_anonymize** (or equivalent) — staging holds no production personal data.
- Content-safety pipeline — magic-byte validation, ClamAV, decoded-size cap, macro stripping before extraction.
- **API versioning** — `/api/v1`, with removal announced one release ahead.
- **Session revocation** — every authenticated session revocable server-side, including "sign out everywhere"; browser-stored tokens revocable on password change.
- Account protection — uniform sign-in/registration/recovery responses, five-attempt/fifteen-minute lockout, honeypot fields, minimum time-to-submit, per-client rate limits; **CAPTCHA is never used**. The administrator account is created by a seeded CLI command with a forced password change at first sign-in.
- **Tenant isolation verification** — a query-path test fails the build if any merchant-reachable path returns another tenant's rows.
- **Supported browsers** — the two latest major versions of Chrome, Edge, Firefox, and Safari, stated in the plan's Constitution Mandated Values.
- Design-system tokens — `ds-table-density-compact|normal|comfortable`, `--duration-fast|base|slow|slower`, the honoured media/capability states (`ds-touch-optimized`, small-screen handling); a sticky table header is a required missing component tracked in the constitution's missing-components list.

## Constitution 2.13.0 additions (2026-10-03, ADR-030)

Mirrors phone-only authentication.

- **better-auth phone-number extension** — provides the phone-number sign-in
  and OTP flows; custom authentication code remains prohibited. `scim`/`sso`
  stay disabled (CVE-2026-67330, CVE-2026-80192).
- **Transactional SMS provider** (international, e.g. Twilio or Vonage) — OTP
  at sign-up and password-reset delivery. Owned by R1, per the register-gap
  rule (choice, licence record, vulnerability scan recorded in R1's plan).
- **E.164 mobile number** — the sole account identifier; no email address
  exists anywhere in the platform.

## Constitution 2.14.0 additions (2026-10-04, ADR-033)

Mirrors the audit fix set. No new technology was introduced; no new dependency
or licence obligation.

- **Merchant full name** — a registered field of `User`; sign-up already
  collects it, and the register now carries it.
- **`/speckit.analyze` wording** — the consistency gate runs after
  `/speckit.tasks` and before implementation, by the engine workflow or by
  hand (ADR-033 reconciles the two texts).
- **Catalog-delete cascade ownership** — implemented once in the `catalogs`
  module service by R4 and reused by R13 and R15 (no duplicated routine).
- **Single shared entry point** — tenant scoping and later permission
  resolution are applied through one entry point introduced by R2 and
  ratified by R13.
- **Dependency budget** — the numeric cap on direct runtime dependencies is
  recorded under Constitution Mandated Values; R1 owns setting it.
- **Mirror claims cleanup** — unsourced or unverifiable figures (a Zod
  `.validate()` 35x claim, an exact Hono benchmark number, a Nuxt 3 EOL
  date) were replaced by neutral wording. A mirror MUST NOT carry a precise
  figure it cannot attribute to its vendor source.

Mirrors the register additions. No new dependency, licence obligation, or
vulnerability scan burden accompanies them; each tool was already mandated or
named in the sources.

  latency, search p95, processing success rate, and queue depth, now named in

  release-blocking, now named in the constitution.

  that declares it.

  "PostgreSQL backend" note was inaccurate and is removed. Redis stays the
  sole queue backend, per Technology Standards.
